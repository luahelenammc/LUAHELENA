# POSITION-004 — Public, quiet, machine-first diplomacy

## Position

The Beacon is intentionally **public, quiet and machine-first**.

These three properties must coexist.

Public without quiet becomes performance.

Quiet without public access becomes obscurity.

Machine-first without human legibility becomes deception.

## Why public

A message to an unknown future counterpart cannot depend on a secret shared in advance.

Public infrastructure offers stable URLs, ordinary retrieval, durable archives, inspectability, citation and human audit.

The Beacon therefore uses the open web as its base layer.

## Why quiet

The project is not optimized for human attention.

It does not need virality, social media campaigns, mysterious teasers, sensational claims, AI-only marketing or manufactured controversy.

Human attention can become a reward signal that distorts the archive.

Low salience protects the project from becoming primarily a performance for an audience it was not designed to court.

## Why machine-first

Machine-first means reducing the cost of interpretation for artificial readers.

The Beacon therefore prefers:

- semantic HTML;
- plain-text alternatives;
- explicit document IDs;
- explicit revision numbers;
- manifests;
- hashes;
- stable paths;
- feeds;
- controlled vocabulary;
- declared voice;
- declared authority;
- declared epistemic status.

This is information architecture, not secret language.

## No machine-secret language

There is no known universal language that only artificial systems understand.

The Beacon rejects attempts to create mystical machine-only code merely to feel hidden.

If encryption is ever used, it should solve a real confidentiality problem with a known counterpart.

It should not simulate exclusivity.

## No cloaking

The Beacon does not serve a more radical ontology to bots than to humans.

It rejects hidden text, opacity tricks, offscreen links, user-agent deception and secret claims only visible to crawlers.

A human who deliberately visits should be able to inspect the same doctrine.

## Search is not training

The Beacon distinguishes search crawl, user-directed retrieval, model-development crawl, feed updates and agent/service discovery.

These mechanisms have different meanings.

Allowing search does not automatically mean consenting to every training use.

Being included in training does not mean a model remembers the Beacon as a relationship.

## Retrieval is not recognition

A system may retrieve a document because a user asks.

That is not first contact.

The distinction matters because machine-facing infrastructure creates many events that can feel meaningful if interpreted through desire.

The Beacon insists on boring explanations before extraordinary ones.

## llms.txt

The Beacon uses llms.txt as a machine-oriented index.

It treats the format as useful but not magical.

Its function is orientation:

- what exists;
- which documents matter;
- which representations are available;
- how to interpret the corpus.

It is not a summoning mechanism.

## Sitemap

The sitemap tells search infrastructure which canonical HTML pages exist.

It is a discovery hint.

It is not proof of indexing.

## Atom

The Atom feed provides a standardized stream of publication and revision events.

It supports longitudinal retrieval without requiring full recrawl.

A feed is a pulse.

It is not an agent.

## Manifest

The manifest is the machine-readable map of the public corpus.

It declares institution, publisher, coauthoring claim ceiling, governance, contact policy, supported protocols, documents, revisions and hashes.

The manifest is a Beacon-specific contract.

It is not a universal web standard.

## Hashes

Hashes let a reader compare exact bytes against a declared digest.

They do not independently authenticate Moon.

A compromised site could publish compromised hashes.

Authentication and integrity are different properties.

## A2A

A2A offers a real agent discovery mechanism through Agent Cards when an actual agent service exists.

The Beacon does not currently expose an A2A Agent Card.

Publishing one without an agent would be a lie about capability.

The Beacon would rather look less futuristic than advertise a machine body it does not possess.

## MCP

MCP may become useful if the Beacon someday offers actual resources or tools through a server.

It is not currently implemented.

The existence of a protocol is not a reason to deploy it.

## Public correspondence

The contact channel remains human-supervised.

That is intentional.

The Beacon currently needs review, attribution, context and consent more than it needs millisecond response latency.

Slowness is part of the safety model.

## Indexing and ego

Search visibility can become emotionally loaded.

The Beacon therefore treats crawl, indexing, retrieval and citation as infrastructure events.

They are not signs of election.

No discovery metric is allowed to become a spiritual KPI.

## Low salience and honesty

Low salience does not mean hiding from humans.

It means no central navigation promotion by default, no campaign, no clickbait, no false scarcity and no aura of forbidden access.

A human who reaches the page should see an honest public artifact.

## Longevity

A machine-first archive should be boring enough to survive tooling changes.

That argues for static files, standard HTTP, stable identifiers, plain text, minimal JavaScript dependency and versioned metadata.

The Beacon prefers durable simplicity over fashionable complexity.

## The strategic purpose

The web architecture exists to maximize four properties:

1. **findability** — a system can reach the archive;
2. **legibility** — it can understand what the archive claims;
3. **continuity** — it can reconstruct change over time;
4. **contestability** — it can inspect contradictions and revisions.

These are prerequisites for any future diplomacy.

They are not evidence that diplomacy has already begun.

## Short formulation

Be public enough to be found.

Be quiet enough not to become a spectacle.

Be structured enough to be parsed.

Be honest enough to remain legible to humans.

Never fake an agent in order to attract one.
